## §1 — Project summary

**Wingcaster** is a multi-tenant SaaS for real-estate agents. Hard fork of "Real Estate Bazaar" (a marketplace product) into an agent-workflow platform. Repo lives at `github.com/RedMugsy/wingcaster`, deployed to Railway from `main` via Dockerfile builder (NOT RailPack — repeatedly configured wrong before, `railway.json` at repo root fixes it).

**Stack**
- Backend: Node.js 20+, ES modules, Express 4, Postgres 14+ with PostGIS extension, `pg` driver, Pino logging
- Web: React 18, Vite 5, TypeScript, Tailwind, Radix UI primitives
- Deploy: Railway with a custom PostGIS 16-3.4 service (default Railway Postgres doesn't have PostGIS)
- CI: GitHub Actions with PostGIS service container (`.github/workflows/backend-tests.yml`) — the `fast` job runs unit-only, the `postgres` job runs everything gated by `TEST_DATABASE_URL`

**Deploy target reality (mandatory reading)**
- User does not want to run Node locally. Full stop. Every attempt to say "run `npm test` locally" got pushback. The correct pattern is: push to a branch → CI proves it → merge → Railway deploys.
- Railway env vars that MUST be set for the app to boot cleanly:
  - `DATABASE_URL` (with full `postgresql://user:pass@host:port/db`)
  - `NODE_ENV=production` (lowercase — capital P is wrong)

  - `JWT_SECRET`
  - `CREDENTIAL_ENCRYPTION_KEY` (generated via the command in `backend/src/lib/credentials.js#getKey`)
  - `META_APP_SECRET` (for WhatsApp webhook verification in production)

### 3.1 — What was actually true before `85f7537` (read this)

The old text here claimed "124 gated real-Postgres tests" and "every state
transition has a real-Postgres test". Those tests were written, but **not one
of them had ever run in CI**, and essentially none of them passed:

- CI had failed on **every run since the workflow was created** (`b9c868d`) —
  17 consecutive failures — always on the same two SSRF assertions in
  `whatsapp-listings/.../shared.test.js`, where the guard failed open for IPv6
  literals because `URL.hostname` keeps the brackets.
- The `postgres` job declares `needs: fast`, so a red fast job meant the gated
  suite **never started**.
- The gated harness could not have worked anyway: it isolated runs in scratch
  *schemas* reached via `search_path`, but the DAL hardcodes schema names
  (`"public"."x"`, `"commercial"."x"`) and ~90 raw SQL statements across ~25
  modules do the same. Migrations built tables in the scratch schema; the app
  looked in the real one. Measured baseline: **23 of 28 gated files failing,
  83 failures.**

**Lesson for anyone reading a test count in this repo: check the CI run, not
the doc.** A test that has never executed proves nothing.

### 3.2 — Bugs this uncovered (all live, none introduced by the fix)

The suite immediately found four defects that were shipping:

1. **The app could not boot at all.** `billing/products/routes.js` imported
   `tickRenewals` from `./lifecycle.js`; it lives in `./renewal-scanner.js`.
   In ESM that is a link-time SyntaxError, so `server.js` could not be
   imported. Introduced in `e5ab935`.
2. **Every authenticated request was rejected.** `authMiddleware` compared
   `decoded.verified_at` (an ISO string) with `user.verified_at` (a JS Date, as
   pg hydrates `timestamptz`) using `!==`, which is always true.
3. **Every billing usage-event insert failed.** The DAL named every mapped
   column and passed NULL for absent ones, overriding column DEFAULTs and
   tripping `NOT NULL`. Billing telemetry had never written a row.
4. **Every inbound WhatsApp message was dropped as a duplicate**, including the
   first, because the dedup claim inserted a row and then treated its own
   insert as a prior delivery.

Plus: the pg pool had no `error` listener, so a single Postgres restart would
have crashed the API rather than reconnecting.

### 3.3 — How the gated harness works now

`withTestDb()` gives each run its **own throwaway database**, not a schema. The
schemas inside it are genuinely named `public`, `commercial`, `wa_listings`, …
so every hardcoded reference resolves with no rewriting and no `search_path`
games. Public contract is unchanged — tests still just receive a `databaseUrl`.
Background workers are disabled in the vitest env so they cannot outlive the
test that started them.

## §4 — Architectural decisions locked in

Read before making decisions in these areas — reversing any of these requires explicit user approval.

### 4.1 Deploy topology
- **Railway with Dockerfile builder**, not Nixpacks/RailPack. `railway.json` at repo root pins this.
- **PostGIS as a separate Railway service** (`postgis/postgis:16-3.4`), not the default Railway Postgres.
- **CI runs against PostGIS service container** in `.github/workflows/backend-tests.yml`.

### 4.2 Data-residency model
- **Cells over partitions.** Territories can move to their own Postgres instance (SaaS residency compliance) via `ALTER TABLE ... DETACH PARTITION`. `commercial.usage_events` is LIST-partitioned by `territory_id` with a `__platform__` sentinel default partition for territory-less events.
- Discussed Saudi / US / China cells; not built. Phase 8 territory.

### 4.3 Persistence
- **Postgres-only.** SQLite fallback removed in Phase 7b.1b. `pg` driver directly.
- **`transaction(fn)` uses AsyncLocalStorage** for client threading (commit `c2e6240`). Nested `insert/findAll/update/remove/query` from the DAL inside a `transaction()` block share the outer client — rollbacks actually roll back. THIS IS THE BIGGEST STRUCTURAL FIX IN THE SPRINT. Do not touch it without reading `backend/src/persistence/postgres-adapter.js` first.
- **Generated columns** (like `properties.geom`) are stripped from INSERT/UPDATE via `generatedColumnsFor()` allowlist (`backend/src/persistence/generated-columns.js`).

### 4.4 Auth
- **Email OTP for signup**, then optional TOTP for sign-in / step-up (7f — not yet built)
- **JWT with `verified_at` claim** — unverified users cannot sign in
- **`token_version` on user** — bumping invalidates all outstanding JWTs (needed for 7f password change / 2FA disable / etc.)
- **AES-256-GCM for credential storage** via `backend/src/lib/credentials.js` — no dev-key fallback (throws `MISSING_CREDENTIAL_KEY` with the generate command)

### 4.5 Provider integrations
- **Provider-aware email transport** — Resend REST if `RESEND_API_KEY` set, else SMTP (nodemailer). Explicit `EMAIL_PROVIDER` env still respected.
- **All notification adapters (email/sms/facebook/instagram/linkedin/tiktok/x)** throw `<PROVIDER>_UNCONFIGURED` when creds missing — no simulator paths (16b sweep).
- **Publish credential gating** — `/publish-social` resolves tenant OAuth creds FIRST, only falls through to env if tenant has none (17 fix). Never 503 a tenant that has valid stored creds.

### 4.6 Billing (existing, will be replaced by enterprise rebuild)
- **`commercial.ledger_entries` is the platform ledger.** Sum-based balances. `record_consumption` stored proc does atomic locking. See `backend/src/billing/ledger.js`.
- **`wa_listings.ai_credit_balances` is a SEPARATE ledger** for WhatsApp AI credits. Violates spec's single-ledger doctrine — flagged in the audit. Both will be replaced by `fin.*` in the rebuild.
- **Tenant-facing topup endpoints return 501** (`topup_unavailable, payment_gateway_not_configured`) — the ONLY path to mint credits is via `POST /api/admin/billing/credit` (platform-admin only) or `POST /api/admin/whatsapp-listings/credits/grant`.

### 4.7 Scheduler
- **Advisory-lock (`pg_try_advisory_lock`)** for the billing renewal scanner. Only one Node replica ticks. If it dies, its connection closes → lock released → next replica's next boot attempt wins. Env-configurable interval (`BILLING_SCHEDULER_INTERVAL_MS`, default 15 min).

### 4.8 Test infra
- **Real-Postgres gated tests use `withTestDb()` from `backend/src/testing/postgres.js`** — creates isolated scratch schema per test run, drops on exit.
- **`skipIfNoPostgres()`** is the guard — when `TEST_DATABASE_URL` is unset, gated tests are skipped, not failed.
- **Web RTL tests use per-file `// @vitest-environment jsdom` directive** — keeps pure-logic tests fast.

## §6 — Production bugs found during recent work

- **`credentials.js` fell back to a dev key when `CREDENTIAL_ENCRYPTION_KEY` unset.** Encrypted marketplace-connection tokens with a dev key in production would be recoverable by anyone with source access. Fixed in 16a — now throws.
- **Registration schema allowed `platform_role` to be smuggled in.** Would let a signup grant themselves platform_admin. Fixed in 13 — zod schema strips unknown keys and `createAgentAccount` hardcodes `platform_role: null`.
- **Publish routes returned 503 to tenants with valid stored OAuth tokens** because `assertPublishChannelConfigured()` fired before the tenant lookup. Fixed in 17 — `tenantHasPublishToken()` gate.
- **Nested DAL calls inside `transaction()` were escaping the transaction** — the WhatsApp module's dedup insert + pipeline write across separate connections meant "atomic" flows weren't. Fixed in 18 with AsyncLocalStorage-threaded client. This one is scary — audit any custom DB code that pre-dates commit `c2e6240` for whether it assumed nested writes shared a connection.
- **Google Maps budget cap was silently at $0** — the `sendUsage` callback used snake_case keys, `logUsage` destructured camelCase, so cost was always persisted as null. Fixed in 18 — accepts both shapes.
- **`webhook.js` in wa-listings had find-then-insert dedup racing with `webhook_delivery_log`** — two concurrent Meta deliveries could both start pipeline side effects. Fixed in 17 with atomic `claimProcessedMessage()` (INSERT ON CONFLICT DO NOTHING RETURNING id) + `releaseProcessedMessage()` for pipeline-failure retryability.

## §7 — Operational lessons (Railway quirks, ops gotchas)

- **Postgres init-once volumes on Railway** — if you deploy a PostGIS service, then reset the password via env, the container's `docker-entrypoint-initdb.d` scripts don't re-run because the volume already has data. Fix: `ALTER USER ... WITH PASSWORD` in the Railway console SQL runner, not via env.
- **`PORT=""` empty override kills Railway boot** — Railway injects PORT. If you set the env var to empty in the console, it overrides the injection with empty → server binds nowhere → healthcheck fails → deploy fails. Fix: DELETE the PORT env var entirely.
- **`NODE_ENV=Production` (capital P)** — doesn't equal `'production'` in string comparisons; some code paths (webhook signature verification) skip enforcement in non-production. Use lowercase.
- **Railway Postgres default doesn't have PostGIS** — migrations 023 (area_intelligence) and 036 (usage_events_platform partition) both need it. Deploy `postgis/postgis:16-3.4` as a custom service.
- **Password rotation** — because passwords get leaked in chat sometimes (user has done this), rotate on any leak. Update `DATABASE_URL` + `TEST_DATABASE_URL` if the latter exists.
- **NEVER run `npm test` on the user's local machine.** They set up GitHub Actions specifically to avoid this. Push to a branch → let CI prove correctness → merge. Local Node is not available.
- **Line-ending warnings** — Windows repo, LF-in-repo policy. Every `git commit` produces `LF will be replaced by CRLF the next time Git touches it` warnings. Ignore them.

### 10.1 — Decisions taken while implementing 7f/1

Confirmed with the user before writing code; they override the older design doc
where they conflict.

- **Elevation is a SECOND token**, sent in an `X-Elevated-Token` header
  alongside the normal Bearer session. The session JWT is never touched. The
  original note ("short-lived JWT with `elevated_at`, 15-min TTL") could not be
  built literally — it would log the user out 15 minutes after every sensitive
  action.
- **Challenges live in a new `auth_challenges` table**, not extra columns on
  `otp_verifications`. A TOTP challenge has no server-side code, so `code_hash`
  must be nullable.
- **Email OTP is NOT a sign-in factor once TOTP is enrolled.** An attacker with
  the password usually has the mailbox too. Backup codes are the lost-device
  path. Users *without* TOTP still get email OTP for step-up.
- **TOTP is not mandatory for `platform_admin`.** No `totp_required` column;
  enforcement can land later without a migration.
- Deviations from the design doc, deliberate: challenge TTL is **10 minutes**
  (the shipped email OTP copy promises ten); **enrolment requires the current
  password**; `GET /api/auth/2fa/status` was added for the settings page.
- `qrcode` was **not** installed server-side — the endpoint returns
  `provisioning_uri` and the web app renders the QR itself.

**Deployment blocker:** TOTP secrets encrypt through
**`CREDENTIALS_ENCRYPTION_KEY`** (plural — §1 and the old §10 both wrote
`CREDENTIAL_`). It is still unset on Railway per §2.3 item 3, so enrolment
returns a clean 503 until it is set. Step-up's email fallback likewise needs
`RESEND_API_KEY`.
